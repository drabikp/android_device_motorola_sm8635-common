# Plain entry, NO flags -- deliberately. Two things were tried here and both
# broke the device; do not re-apply either.
#
# The blob is compiled against android.hardware.wifi-V1-ndk while AOSP's own
# android.hardware.wifi-service uses V4, and soong merges the paired prebuilt and
# source graphs and refuses "multiple versions of the same aidl_interface".
#   * ;MODULE_SUFFIX=_arcfox unpairs them, which un-suppresses AOSP's module:
#     two installers for this path plus a competing V4 VINTF fragment.
#     (;OVERRIDES cannot fix that -- extract_utils only honours OVERRIDES for
#     android_app_import.)
#   * ;DISABLE_DEPS drops EVERY dependency edge, not just the wifi-V1 one, so
#     libwifi-system-iface stopped being installed into /vendor/lib64 and the HAL
#     crash-looped at exec:
#       CANNOT LINK EXECUTABLE: library "libwifi-system-iface.so" not found
#     It survived a static pre-flash check because that library does exist in
#     /system/lib64 -- which a vendor process cannot link from.
# The single V1 edge is now removed surgically by a lib_fixup in
# extract-files.py, which leaves every other edge intact.
#
# DISABLE_CHECKELF follows from that and nothing more: with the edge removed,
# check_elf_file sees a DT_NEEDED with no matching shared_libs entry
#   error: DT_NEEDED "android.hardware.wifi-V1-ndk.so" is not specified in shared_libs
# It is the narrow flag -- it silences that one consistency check and does not
# touch the dependency graph the way DISABLE_DEPS does. The library is shipped
# by common.mk (android.hardware.wifi-V1-ndk.vendor); confirm it is in
# out/target/product/arcfox/vendor/lib64 if you ever change this.

# there is no wlan0 at all:
#   ueventd: firmware: could not find firmware for wlan/qca_cld/kiwi_v2/WCNSS_qcom_cfg.ini
#   cnss: Failed to probe host driver, err = -1
# On stock that directory holds THREE symlinks, and extract_utils silently drops
# symlinks -- which is why neither the links nor the kiwi_v2/ target directory was
# ever extracted:
#   WCNSS_prc_cfg.ini  -> /vendor/etc/wifi/kiwi_v2/WCNSS_prc_cfg.ini
#   WCNSS_qcom_cfg.ini -> /vendor/etc/wifi/kiwi_v2/WCNSS_qcom_cfg.ini
#   wlan_mac.bin       -> /mnt/vendor/persist/kiwi_v2/wlan_mac.bin
# Only the two .ini files are restored here. wlan_mac.bin CANNOT be shipped as a
# real file -- it has to resolve into /mnt/vendor/persist, which needs a genuine
# symlink (install_symlink or LOCAL_POST_INSTALL_CMD). It is left out because
# wlan0 comes up with a correct Motorola MAC without it, and
# /mnt/vendor/persist/kiwi_v2/ does not even exist on this device; revisit only if
# the MAC ever turns out to be random across boots.
# Shipped as four real files rather than links: the firmware loader reads them
# during early boot and a plain file has no resolution order to get wrong.
# Do not "clean this up" back into symlinks without re-reading that trap.

# --- DISPLAY STACK: ALL STOCK, DELIBERATELY -----------------------------------
# Every SDM support library in this image is a BIT-IDENTICAL stock blob
# (libsdmcore.so, libsdmutils.so, libgralloc.qti.so, libdisplayconfig.qti.so,
# libqservice.so, libhistogram.so, ...). sdm::CoreInterface and
# sdm::DisplayInterface are private, unversioned C++ vtables, so the composer
# binary MUST come from the same tree as those libraries.
#
# Building vendor.qti.hardware.display.composer-service from
# hardware/qcom-caf/sm8650/display instead produced exactly the mismatch you
# would expect: the source-built composer SIGSEGV'd six frames inside the stock
# libsdmcore.so, on its very first core_intf_->CreateDisplay() call, with zero
# log output -- 82 times in 402s. Its .rc has `onrestart restart surfaceflinger`
# and surfaceflinger's has `onrestart restart zygote`, so it tore down
# SF -> zygote -> system_server every 5s and the boot could never complete.
#
# Same failure class as the keymint V3-vs-V4 ABI break: do not mix a
# source-built consumer with prebuilt providers of a private interface. Ship
# the whole display stack from stock, or build all of it -- not half of each.
# (The official peridot device ships this composer as a blob too.)
#
# The AIDL/HIDL interface libraries the composer needs are NOT blobs: each of
# them is generated by an aidl_interface/hidl_interface already in the tree, and
# a prebuilt of the same name collides ('partition is different: system(...) !=
# vendor(prebuilt_...)'). They are declared in common.mk as source-built .vendor
# variants instead -- the same treatment as the display.config-V* libs. AIDL
# generated code at a FIXED version is ABI-stable, so unlike libsdmcore this is
# not a mixed-tree hazard.
# DISABLE_DEPS: the composer links composer3-V2 itself while something in its
# closure pulls V4, and soong refuses "multiple versions of the same
# aidl_interface". The file still installs; soong just stops modelling its
# deps. This is how the official peridot device ships this same binary.
vendor/bin/hw/vendor.qti.hardware.display.composer-service;DISABLE_DEPS

# The power HAL binary and its .rc were shipped, but this manifest fragment was
# not, so nothing DECLARED android.hardware.power.IPower/default:
#   servicemanager: Could not find android.hardware.power.IPower/default in the
#   VINTF manifest. No alternative instances declared in VINTF.
#
# HintManagerService then takes an unguarded AOSP path:
#   createIPower() -> ServiceManager.waitForDeclaredService(...) -> null
#   mSupportInfo stays null -> mSupportInfo.headroom -> NullPointerException
#   RuntimeException: Failed to create service HintManagerService
# which is FATAL to system_server, 58 times, 21 lines into startOtherServices --
# after PHASE_WAIT_FOR_DEFAULT_DISPLAY (100) completes. A device with no declared
# power HAL simply cannot boot Android 16.
#
# Version 4 is correct and sufficient: compatibility_matrix.8.xml requires
# android.hardware.power v4, and HintManagerService has an explicit
# mPowerHalVersion == 4 fallback that synthesises a valid SupportInfo.
#

# source-built android.hardware.power-service-qti, so shipping stock's fragment at
# that path is a hard kati collision ("overriding commands for target"). That

# it -- which is precisely why the manifest ended up missing from the image.
# VINTF merges every *.xml in the fragment directory, so the name is irrelevant;
# only the content matters. Keeping the stock BLOB (which links power-V4-ndk,
# matching compatibility_matrix.8's requirement of v4) rather than switching to

# --- WEAVER (Thales) DROPPED: it wedged system_server every 94 seconds ---------
# Its vintf fragment DECLARED android.hardware.weaver.IWeaver/default, but the
# service can never start: the rc marks it `disabled` and the only boot trigger is
#     on init && property:ro.vendor.hw.felica=false
# and ro.vendor.hw.felica is set NOWHERE -- not in any build.prop, and stock's
# init.mmi.rc maps ro.boot.* -> ro.vendor.hw.* for device/hwrev/modelno/revision/
# nav_keys but NOT felica. The only other trigger is vendor.ese.client.restart=1,
# a runtime restart hook. So nothing starts it, on stock or here.
#
# Declared-but-absent is fatal, not cosmetic: LockSettingsService ->
# SyntheticPasswordManager.getWeaverAidlService() calls
# ServiceManager.waitForDeclaredService() from the system_server MAIN thread while
# holding the SyntheticPasswordManager monitor, inside startOtherServices(). It
# blocks forever; Watchdog then kills system_server:
#     *** WATCHDOG KILLING SYSTEM PROCESS: Blocked in handler on main thread for 69s
# The framework restarted every 94.1 +/- 0.4 s, nine times in one capture --
# regardless of what the user was doing. It only LOOKED like "pressing Next on the
# SIM screen reboots the phone" because the wizard is what happens to be on screen
# when the timer expires. It is not even a reboot: /proc/uptime and dmesg are
# monotonic across the whole capture and init/servicemanager/vold keep their pids.
#
# Weaver is optional (secure-element-backed PIN throttling) and the rest of the
# Thales SE stack was already dropped for AIDL-version conflicts, so the binary
# and rc go too rather than leaving a HAL that can never run.
